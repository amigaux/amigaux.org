## amigaux 1.1.2

Released %DATE_1_1_2%, as packages in the 1.1 repository (`http://pkg.amigaux.org/1.1`). The
1.1.2 install media are available: [Downloads](../downloads/index.md). An installed 1.1 or 1.1.1
system takes 1.1.2 in place with `apkg`.

### What is new in 1.1.2 {#whats-new}

- **MNT VA2000 graphics card**, the module `va2000` and the X server `Xrtg`: Antti Sokero's
  driver (MIT), for both kernel lines. The packages install the card's file
  `/etc/display.d/va2000`, so `xstart` starts X on the card (`Xrtg -card va2000`); with a VA2000
  beside another card, `card` in `/etc/display` chooses. The console stays on the Amiga's own
  display. The card needs its firmware 5 or later. Packages `va2000-k30` and `va2000-k46`,
  1.1.0-2. The VA2000 cannot be emulated: the packages are tested only for their install and for
  a boot with no card fitted, not yet on a real card.
- **X-Surf and X-Surf-100 Ethernet**, `xsurf` 1.0.0-4: the driver reads the X-Surf-100's link,
  its speed and duplex, and says once on the console when the link is lost. The board check at
  start-up is more thorough, and a board that fails it is refused with the reason. New: the
  status tool `xsf`, which prints the board, the link and the counters; pages `xsurf(7)` and
  `xsf(1M)`. On a 1.1 or 1.1.1 system it comes with a second `apkg upgrade`
  ([upgrading](#xsurf-upgrade)). 1.0.0-4 is tested by us in emulation only. Users report an X-Surf-100 working on
  real hardware with 1.0.0-3, the version in 1.1.1, in two A4000D machines, each with a CyberStorm
  68060: in the first it took a DHCP lease and carried traffic both ways; in the second, in
  Zorro III with the system disk on a Buddha, it took its address by DHCP, and ping, telnet and
  ftp worked. [Networking](../docs/networking.md#interfaces).
- **MNT ZZ9000 cards**, with `z3660rtg` 1.1.2-3: a ZZ9000 in Zorro II or Zorro III, also beside
  a Z3660 as its second card, `/dev/zz9001`. `zz9k_probe` tells the boards apart. A Zorro III
  ZZ9000 on the 68030 line needs the 68030 kernel of 1.1.2. Tested in emulation on both lines,
  alone and beside a Z3660, not yet on a real card.

### Updated {#updated}

- `x11r6.3` 6.3-11: one X server, `Xrtg`, for every RTG card, with `Xzz9000` and `X` as other
  names for it; `-card` picks the card (`zz9000`, `va2000` or `auto`) and `-dev` its device node.
  An upgrade keeps the X configuration files you edited and puts the new version beside them as
  `.new`. A TERM sent to `xinit` now ends the session and the server, as a hangup does.
- `amix-base` 1.0-36 (1.1.1 had 1.0-34): `xstart` picks the display by each card file's probe
  line, ends a server that `xinit` left running, and tells a server that ended on its own from a
  session that `xinit` ended; `shutdown` waits until the system has changed state
  (`initwait(1M)`); `interfaces(4)` lists the network interfaces.
- The kernels: 68040/68060 `kern46m` -67, 68030 `kern30m` -78. A root that cannot be mounted
  stops the system with one panic, not two. On the 68030, a program's access to a Zorro III
  board's memory no longer ends in a bus error at random; on the 68040/68060, a driver can map a
  Zorro III card's framebuffer for faster drawing. The 1.1 and 1.1.1 module packages keep working
  with the new kernels, on both lines.
- `kbootset` 1.1.0.261115-46: knows the VA2000 driver, and `apkg` installs it before the VA2000
  packages; `kbootset(1M)` describes moving the system disk to another controller.
- `APKG` 0.3.13: a plain `apkg upgrade` repairs an install or upgrade that was cut short; `apkg
  list` and `apkg info` mark such a package `[partial]`.
- `z3660rtg` 1.1.2-3: the ZZ9000 support above; X's card files for the Z3660 and the ZZ9000
  carry a probe line. On a Z3660 running its emulated 68030 (the 68030 kernel line) the Z3660's
  graphics are now found automatically; 1.1 and 1.1.1 found them there only with `param fixed=1`
  set by hand. The module parameter `fixed` is now a number: 0 finds them automatically (the
  default), 1 works as before, -1 never looks ([upgrading](#upgrade)).
- `prngd` 0.9.29-4: an upgrade keeps an edited `prngd.conf`.

### Known limits {#known-limits}

- **A shutdown can stop after the change of run level and never halt.** Occasionally the console
  stays at `INIT: New run level: 0` (`who -r` shows run level 0), but the shutdown scripts do not
  start. Why is not yet known. So far it has been seen on a 68030 system with 16 MB of memory after
  heavy writing; it is not new in 1.1.2, as 1.1.1 behaves the same. The 68040/68060 line runs the
  same init and has not been tested for it. Running `shutdown` or `/sbin/init 0` again does not
  help. Wait: it sometimes goes on by itself after some minutes. If it does not, run `sync` if a
  shell still answers, wait until the disk activity stops, and switch off; the file systems are
  checked at the next boot.
- **If the X server on a VA2000 is killed or crashes, the console keyboard may not come back**,
  as on the other RTG cards; this follows from the server's code and has not been tried on a
  card. `/opt/amix/bin/rtg-kbdback`, which gives it back, is installed by the `z3660rtg`
  packages, not yet by the X package; a normal end of the session, or ending it with a signal to
  `xinit`, hands the keyboard back.

### Corrections {#corrections}

- **Memory limits.** On the kernels of 1.1, 1.1.1 and 1.1.2, on both lines, a program's data and
  address space have no limit by default, soft or hard; only the stack is limited, to 16 MiB
  (`ulimit -a` shows it). Earlier texts, the [1.1 release notes](1.1.md) among them, said a
  program gets the original 16 MiB of data and address space by default; that was wrong, and they
  are corrected. To set a limit yourself, use `ulimit -d` (data) and `ulimit -v` (address space),
  with a size in KiB, in the shell or in your profile (`/etc/profile` for everyone). A later
  kernel brings the original 16 MiB soft limits back as the default, with the hard limits
  unlimited so that they can be raised.

### Upgrading {#upgrade}

As root, in this order:

1. `apkg update`
2. `apkg upgrade`: it takes every 1.1.2 package your system has.
3. Restart, to run the new kernel.
4. With an X-Surf: `apkg upgrade` once more ([below](#xsurf-upgrade)).
5. For a VA2000: `apkg install va2000-k46` on a 68040 or 68060, `apkg install va2000-k30` on a
   68030.
6. After step 4 or 5, restart again.
7. `xstart` starts X.

<span id="xsurf-upgrade"></span>**The X-Surf driver comes with the second `apkg upgrade`.** On a
1.1 or 1.1.1 system the first `apkg upgrade` updates everything except the X-Surf driver, and says
`xsurf-k46 1.0.0-4 is left out: the catalog entry is refused: only a kernel entry may carry
kbootset=` (`xsurf-k30` on the 68030 line): the package manager that system still has, older than
0.3.13, does not accept the new driver's catalog line. Run `apkg upgrade` a second time, after the
first has installed the new package manager: it then takes `xsurf` 1.0.0-4. Until then the
installed driver keeps working with the new kernel. Only a system with the `xsurf` package
installed sees this.

**The VA2000 only after the upgrade.** On a system not yet upgraded, `apkg install va2000-k46`
prints

```
apkg: va2000-k46: the catalog entry is refused: only a kernel entry may carry kbootset=
apkg: nothing was changed
```

and changes nothing (the same with `va2000-k30` on the 68030 line). The message does not say what
to do: run `apkg upgrade` and restart first, then the same command installs it.

Update `z3660rtg`, `amix-base` and `x11r6.3` together; a plain `apkg upgrade` does. With the older
`z3660rtg`, the new `xstart` cannot start X on the Z3660's graphics.

**Note:** an existing line `param fixed=1` in `/etc/conf/modreg.local.d/z3660rtg` keeps working.
A line spelled `fixed=yes`, `fixed=on` or `fixed=true` must be rewritten as `fixed=1`; otherwise
`kbootset` refuses to build the next boot generation, with `fixed=yes is not a valid int value
for module z3660rtg`, and the system keeps booting the current one.
