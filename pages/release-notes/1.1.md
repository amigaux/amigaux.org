## amigaux 1.1

Released 2026-11-10, on [GitHub](https://github.com/amigaux/amix-media/releases/tag/1.1).
Tested on real hardware: an install from the install CD, burned to a disc, on an A4000, and the
68060 image on an A4000T with a Z3660. Tested in emulation: the 68030 image on an A3000, the IDE
images on an A1200 and an A4000, and the install CD on an A1200, started from the boot floppies.

**1.1 is a clean install.** It replaces a 1.0 system; there is no upgrade. Back up first:
[coming from 1.0](../install/from-1.0.md).
From 1.1 on, later releases upgrade an installed 1.1 system in place, with its packages through
`apkg`: 1.1 is the last release that only installs clean.

### What is new

The short list: [what's new in 1.1](../whats-new/index.md).

- **Ready-installed disk images**: the 68060 image for a Z3660, the 68030 image for an A3000, and
  two IDE images for the IDE port of an A1200 or A4000.
  [Downloads](../downloads/index.md).
- **One install CD for every machine and both lines**, started from two floppies or a Z3660
  boot disk, or by itself through an A4091 boot ROM that carries a CD filesystem; it finds the
  controllers and disks by itself, takes only a 1.1 disc for the machine's line, offers a disk's
  own size and refuses a root too small for the set. A **network install** takes the packages from
  the repository. [Install](../install/index.md).
- **SSH**: every install runs the Dropbear SSH server, with `ssh` and `scp`.
  [Remote login](../docs/services.md#remote-login).
- **Time from the network**: `ntp=yes` sets the clock at boot and hourly.
  [The clock](../docs/services.md#the-clock)
- **Drivers as packages, kernels with a safety net.** The kernel and every driver are packages,
  updated with `apkg`. A new kernel is tried once and the system falls back to the last good one by
  itself; the boot loader has a menu and a safe mode. [Boot recovery](../docs/modules.md).
- **Networking with DHCP.** Every network card is set up from `/etc/inet/interfaces`, by DHCP
  unless you give a fixed address. [Networking](../docs/networking.md).
- **One place for services.** `/etc/rc.conf` switches the added services on and off.
  [Services](../docs/services.md).
- **Your settings survive updates.** An update keeps a configuration file you changed and puts the
  new default beside it as a `.new` file.
- **Disks.** `ufs` everywhere, `/home` on its own partition, file systems up to 2047 MiB and files
  up to 2 GiB. [Disks](../docs/disks.md).
- **X** starts with `xstart`, from `/etc/display`. [X and RTG](../docs/x11.md).
- **Sound**: Paula's four channels for one program, `/dev/paula`, and the original sample-stream
  device, `/dev/audio`. [Sound](../docs/sound.md).
- **Packages** come from a tree of their own for 1.1, `http://pkg.amigaux.org/1.1`.
  [Packages](../packages/index.md).
- **Manual pages** for the added software, and all of them [on this site](../man/index.md).

### Fixed

These faults came with Amix 2.1c and are still in 1.0. The 1.1 kernels (68030-261106-77 on the
68030, 68060-261106-66 on the 68040/68060) and packages fix them. There is no update from 1.0, so
a 1.0 system keeps them until it is installed afresh with 1.1.

- **Files: a large file rewritten in place could read back wrong while memory was short.** The
  data on the disk stayed right; what a program read back could be wrong, and the disk was wrong
  too only if a program wrote back what it had read (Vim's swap file did that). Until you move to
  1.1, do not rewrite large files in place on a machine short of memory.
- **Files: writing into the middle of a sparse file could expose old disk contents**, including
  the data of deleted files.
- **Memory: a program that ran short of memory could have its data overwritten** without any
  error (Vim saved files with lines missing). Fixed by `libcfix`, in the base set.
- **68030 only: a machine short of memory, 16 MB in particular, could hang**, most often during a
  network install.
- **68040/68060, SCSI disks: reading past the end of a slice could hang the program** so that it
  could not be killed.
- **FTP: a download from an Amix server could lose its last bytes**, though the server reported
  the transfer complete (`226`). Fixed by `ftpdfix`, in the base set.

Also fixed: the original `/dev/audio` driver no longer panics the kernel on a request with no
data, answers each volume or speed request once, and plays a long write once. Stopping or killing
a sound player while sound is still playing no longer crashes the system (tested in emulation).

### Known limits

A file system holds at most 2047 MiB; another bootable disk can win over a new install; a
program's data and address space have no limit by default, only its stack, at 16 MiB, and
`ulimit -d` and `ulimit -v` set one (corrected %DATE_1_1_2%: this said a program gets 16 MiB of
data by default; [the correction](1.1.2.md#corrections)); a program that closes a network
connection right after sending can lose the end, the original `ftp` client's uploads among them;
`crash` does not yet work on the 68060 kernel. A network install's first boot can take over an
hour with the full set. `setclk -p` prints the year as three digits from 2000 on (2026 is 126);
the clock itself is right. Wait for the halted message before switching off: after heavy disk
writing on 16 MB, init can take up to five minutes to act on `shutdown`. If `who -r` still shows
the old run level after 30 seconds, run `/sbin/init 0` again. The full list:
[known issues](../docs/known-issues.md).
