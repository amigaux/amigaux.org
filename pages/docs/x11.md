## X and RTG

X runs on the display card that `/etc/display` names, started by `xstart`. See `xstart(1)`,
`display(4)` and `display.d(4)`.

### Starting X

As root on the console:

```
xstart
```

`xstart` finds the card, checks the mode, and starts the X server and your session. Another mode
for this session only: `xstart 800x600`; it must be one of the card's modes. `xstart -n` shows what
it would run and any mistake in `/etc/display`, and runs nothing.

The first-boot question about X is for the A2410 colour card: answer **n**.

### Which card {#card}

Each card's driver package puts the card's file in `/etc/display.d`: how to find the card, its
server, its modes. The file is the package's; it is not edited. Which card X uses is the `card`
line of `/etc/display`:

- `card auto`, the default: the first card that is there, taking the files in name order, with the
  Amiga's own display (`native`) last. A VA2000 (`va2000`) comes before a Z3660 (`z3660`), and both
  before a ZZ9000 (`zz9000`, `zz9001`).
- A card named by its file, such as `card z3660`: that card, which must be there. With two cards
  fitted, this is how you choose the other one.

A card is there when its device node opens. The Z3660's and the ZZ9000's files also run
`zz9k_probe`, which tells the boards apart, since they share the driver and the node name. The
VA2000's node opens only when a board answers, so its file needs no probe.

### The X server {#server}

One server, `Xrtg`, drives every RTG card: the Z3660's, the MNT ZZ9000 and the MNT VA2000.
`Xzz9000` and `X` are other names for the same program. The name it is started under picks the
card: `Xzz9000` the ZZ9000 or the Z3660, `Xrtg` and `X` the first card it finds. `-card` overrides
both (`zz9000`, `va2000` or `auto`), and `-dev` names the card's device node. The card files give
these options already. The server runs as root. Alt-Esc and Alt-F1 to Alt-F10 switch the system's
screens, and X does not see them. See `Xrtg(1)`.

### On the Z3660 {#z3660}

The `z3660rtg` driver package brings the card's file, `/etc/display.d/z3660`: the modes 1024x768
(the first), 640x480, 800x600, 1280x720, 1280x800, 1280x1024 and 1920x1080, in 16-bit colour
only. The Z3660 shares the monitor with the Amiga's own display: `xstart` switches the monitor to
the card and back when the session ends (`monsw` in `display(4)`). It needs the Z3660's RTG
AutoConfig off (its default) and the `monsw` module.

Tested on hardware on both lines, from 1.1.2. In the Z3660's 68030 mode, with `z3660rtg` 1.1.2-3:
on an A4000T the graphics are found with no setting, and X came up at 1024x768 and ended cleanly.
On the 68060 line, with the final 1.1.2 packages from one plain `apkg upgrade`: on an A4000D the
graphics attach by AutoConfig, and `xstart` brought the default session up on them at 1024x768.

### On an MNT ZZ9000 {#zz9000}

From 1.1.2, with the `z3660rtg` package, in Zorro II or Zorro III. It has two files: `zz9000` for
a ZZ9000 alone, and `zz9001` for a ZZ9000 beside a Z3660, as the second card, `/dev/zz9001`. The
modes are 1024x768 (the first), 640x480, 800x600, 1280x720, 1280x1024 and 1920x800, and 1920x1080
on a Zorro III card, in 16-bit colour only. The card passes the Amiga picture through, so there is
no monitor switch.

Tested in emulation on both lines, alone or beside a Z3660; not yet on a real card. A Zorro III
card on the 68030 line needs 1.1.2's 68030 kernel.

### On an MNT VA2000 {#va2000}

From 1.1.2, with the `va2000` package and its file `/etc/display.d/va2000`: `xstart` runs
`Xrtg -card va2000`. The modes are 1024x768 (the first), 640x480, 800x600, 1280x720, 1280x1024 and
1920x1080, in 16-bit colour only; 1920x1080 needs a Zorro III card. The card passes the Amiga
picture through, and the driver puts it back when the card is last closed, so there is no monitor
switch. The console stays on the Amiga's own display. The card needs its firmware 5 or later.

Not yet tested on a real card: the VA2000 cannot be emulated, so only the install and a boot with
no card fitted are tested, on both lines.

### On the Amiga's own display

Without an RTG card, `xstart` uses the Amiga's own display with the original X11R4 server, as far
as that server goes. This is the 68030 image's display.

### When X ends {#ending}

When the session ends, `xstart` switches the monitor back. When the server ended some other way,
because it crashed or was killed, or because `xinit` stopped it on a signal, `xstart` says which
in one line and runs the card's restore command. When `xinit` itself is killed while the server
still runs, `xstart` ends the server (TERM, then KILL after 10 seconds) before it switches back.
`xstart(1)` has the details.

### Your session

`xstart` runs the first of `~/.xsession`, `~/.xinitrc`, the `session` in `/etc/display`, and the
system's default session, which opens an `xterm` and a window manager (`twm`). Root's own
`.xinitrc`, written at the first boot, starts OPEN LOOK.

### The X11R6.3 package

X11R6.3 brings the `Xrtg` server, `twm`, `xterm`, `xclock`, `xdm`, the usual X tools and the misc,
75dpi and 100dpi fonts, under `/opt/amix/X11R6`. It needs a `ufs` root, and a floating-point unit
for full speed: on a 68LC060, X runs through the kernel's floating-point emulation and the server
takes about 25 seconds to start; the 68LC040 is untested
([acknowledgements](../licences/index.md#acknowledgements)). It is the `x11r6.3` package: the
install CD's *x11* set and the network install's *full* set install it; on any other system,
`apkg install x11r6.3`. Without it, as on a standard install, `xstart` uses the Amiga's own
display.

### Installing CDE {#cde}

From 1.1.3, the Common Desktop Environment is the `cde` package, built with shared libraries like
X11R6.3 and Motif. As root, after `apkg update`, three steps in this order:

```
apkg upgrade apkg
apkg upgrade
apkg install cde
```

The first brings an `apkg` that reads the new dependency rules; without it, `apkg install cde`
stops with `apkg: missing dependency: x11r6.3>=6.3-15.s (needed by cde)` and changes nothing. The
second brings the newer 68040/68060 kernel, without which the CDE File Manager fails at login on
68040/68060 systems. The third installs CDE, and replaces an installed X11R6.3 with the shared one
in the same step. CDE takes about 45 MB more disk on a system that already has X, about 77 MB on
one without. [1.1.3 release notes](../release-notes/1.1.3.md#cde)

### A graphical login at boot

`start xdm` in `/etc/display` starts X11R6.3's `xdm` at boot. `display=no` in `/etc/rc.conf` keeps
it off whatever `/etc/display` says.
Not yet tested on 1.1 hardware.
